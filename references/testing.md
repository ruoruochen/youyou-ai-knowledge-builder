# 可选的隔离验收

只有用户明确要求“测试”“隔离验收”或检验其他Agent时才进入；普通日用搭建只建一套空白库并只读检查。

## 一句话测试入口

> 请用这个Skill做一次隔离验收，确认同名知识库不会相互影响。

Agent从用户/宿主规则解析可写测试目录和已知旧库路径，不要求用户手填CLI参数。只使用虚构样本；测试授权不适用于任何真实日用库、旧库正文、全局路由或真实定时任务。

## 默认运行完整自检

在包目录执行，替换为已核实、正确引用的绝对路径：

```text
python -B scripts/builder.py doctor --timezone <IANA_TIMEZONE>
python -B scripts/selftest.py --work <PERMITTED_WORK_DIRECTORY>/ai-knowledge-tests --protect <KNOWN_EXISTING_ROOT>
```

有多个已知保护根目录就重复--protect；没有已知根目录时可省略，不表示扫描过或保证发现了全部旧库。测试目录不能是实例、Obsidian库、包目录或受保护路径的内部。测试器会新建UUID运行目录并保留报告和测试样本，不删除旧测试。

程序验证同名实例隔离、显式保存、CRUD、归档恢复、历史回退、归属范围、冲突拒绝、身份/路径限制和调度约束。报告哪些实际通过，不能把模板中的历史结果当本次结果。

## 指定两个实例的人工验收

仅在用户特别指定“两套”或要求不依赖自检脚本的Agent试用时执行：

1. 用builder.py create在同一个允许的父目录创建两套同名test实例；每次都传入已知--protect。
2. 保存两次回执，从handoff读取各自root和完整ID；操作前核验。
3. 对第二套取得初始文件清单和哈希，只读确认全范围零笔记。
4. 第一套使用虚构样本验证新增、读取、修改、归档和恢复，必要时验证历史与冲突；第二套始终不写入样本。
5. 再核对第二套文件清单与哈希完全相同且零笔记，给出真实结果、两套完整身份和交接文件。若用户要求核验真实旧库不变，优先文件元数据；未经授权不读取旧库正文。
6. 不删除试验数据或改成正式库；后续明确新建另用一个新实例。

普通接续读取现有handoff，不因执行过测试而把任何测试库变成默认日用库。
