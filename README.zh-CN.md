# AI知识库建造器

在AI里交流，说“记下来”才保存；之后AI可以检索、关联和整理这些知识。内容保存在兼容Obsidian的Markdown文件中，Obsidian负责阅读和编辑。

[English README](README.md) · [执行入口](SKILL.md) · [更新记录](ITERATIONS.md)

## 一句话开始

把这句话发给Cola或其他能操作本地文件的Agent：

> 请按这个Skill帮我搭建自己的AI知识库：https://github.com/ruoruochen/youyou-ai-knowledge-builder

Agent负责读取完整仓库、检查环境、选择已允许的目录、保护已知旧库，并创建一套空白日用知识库。**不需要你填写目录参数、编号、test模式或验收清单。** 如果还没有可写的长期目录，Agent只需请求目录权限。

在Cola中可从能访问工作目录的“项目”会话发起。官方文档确认项目支持文件读写与命令执行；本仓库采用读取完整仓库并执行的方式，未声称已上架Cola技能市场，也尚未完成Cola实机验收。[项目文档](https://docs.colaos.ai/zh/coding-cola/) · [Cola适配说明](references/cola.md)

## 建好以后这样说

- “记下来：……”——保存你明确指定的内容。
- “找一下我之前关于……的想法。”——只查自己的知识。
- “把刚才那条改成……”——修改指定笔记。
- “归档这条”／“恢复这条”——可恢复地整理。
- “继续用这个知识库。”——同一对话接续使用。
- “再新建一套。”——另建一套，保留旧库。

换Agent或新对话时，把建库回执里的 **handoff.json** 交给它，再说“继续用这个知识库”。Agent从文件读取身份，不需要你手抄root或UUID；有多个候选库时，它会让你选一个，不按名字或时间猜测。

## 默认规则

- 普通交流不保存；当次明确“记下来”才新增。修改、归档、恢复只授权指定动作。
- 项目、资产、技能与模板是“我的”；资源、灵感库是外部输入。找我的没有结果也不自动扩大范围。
- 支持新增、列表/详情、检索、编辑、可恢复归档、恢复和历史回退。
- 今日、日报和待处理事项索引已保存的个人内容，不是自动聊天存档。
- 待定决策与已采纳行动分开，保留用户异议和未决问题。
- 初次搭建只建立一套空白日用库，不塞测试内容；不会自动导入旧资料、修改全局默认库或创建真实提醒任务。

## 为什么不会和旧库混用

每套库有独立目录和固定UUID。Agent每次操作都核对目录与完整ID，名字只作显示，时间只作记录。笔记、历史、写入锁和提醒记录留在各自实例。程序拒绝错误ID、跨库运行器、越界路径和符号链接。

这些参数由Agent处理。已知旧库通过受保护路径排除；不会为“找旧库”读取正文或全盘扫描，也不声称发现了所有未告知的旧库。这是工具层防误操作，更强隔离依赖宿主文件权限。

## 如果你要测试别的Agent

另说一句即可：

> 请用这个Skill做一次隔离验收，确认同名知识库不会相互影响。

Agent才会运行独立测试、保存虚构样本并给出真实结果。普通建库不自动跑这一套。[测试细节](references/testing.md)

## 环境与实测范围

Agent需要本地文件读写与命令执行能力，Python3.9+和PyYAML；时区数据缺失时可能需要tzdata。依赖由Agent先检查，并在允许的环境中处理。须获取整个仓库，不只复制SKILL.md。Codex可按其安装规则安装完整Skill，其他Agent可直接读取仓库入口。

现有程序在macOS、Python3.9.6下通过36项回归与35项集成检查。此前无原始对话上下文的独立Agent完成过两套同名库的读写与隔离验收。该结果不代表Cola或所有第三方Agent已经验收。

Obsidian界面连接、真实调度、手机与云同步取决于宿主能力和后续请求，文件层建好不代表这些已经接入。
