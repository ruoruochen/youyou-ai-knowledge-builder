# AI知识库建造器

把AI对话作为入口，明确说“记下来”后才积累到Markdown知识库。Obsidian负责阅读和编辑，AI按规则检索、整理和维护。其他Agent无需原始对话，也能按Skill从零建库。

[English README](README.md) · [执行入口](SKILL.md) · [更新记录](ITERATIONS.md)

## 适合什么时候用

- 新建自己的AI知识库。
- 把完整Skill交给另一个Agent，检验它能否独立完成搭建。
- 同一台电脑反复试建，同时保护现有知识库。

## 同名也能隔离

每次新建都获得独立目录和固定UUID。名字只用于显示，创建时间只作记录，AI不能据此自动选库。所有操作必须同时核对绝对根目录和完整ID。

笔记、历史、写入锁和提醒记录各自留在对应实例。错误ID、用A的程序操作B、原样复制后冒充旧路径、跨目录路径和符号链接均会被拒绝。建库与自检都可重复传入--protect，保护已有库；不修改全局默认库路由。

这属于工具层防误操作，不等同于操作系统沙箱。需要更强隔离时，应将另一个Agent的文件权限限制在测试目录。

## 保存和使用规则

- 普通讨论只读；当次明确“记下来”才新增。修改、归档、恢复只授权指定动作。
- “我的”是项目、资产、技能与模板；资源和灵感库属于外部输入。找我的没有结果也不自动扩大范围。
- 支持新增、列表/详情、检索、编辑、可恢复归档和历史回退。
- 今日、日报和待处理事项索引已保存的个人内容；不是自动聊天存档。
- 待定决策与已采纳行动分开，保留用户异议和未决问题。
- 提醒检查会去重；test模式不绑定真实自动任务，production也需明确请求后适配宿主调度。

## 给另一个Agent使用

下载整个仓库或克隆到用户允许的目录，不要只复制SKILL.md。对方需能读写本地文件并运行Python3.9+，且有PyYAML；时区数据缺失时可能需要tzdata。doctor会先检查环境。

Codex可按环境规则将完整文件夹安装到 `~/.codex/skills/youyou-ai-knowledge-builder`；其他Agent可直接读取SKILL.md。执行入口为英文，详细运行规则、API和默认目录名称为中文。

可以把这段话交给Agent，并替换为自己实际允许的目录：

> 读取本仓库SKILL.md，在我指定的测试父目录创建两套同名test知识库，将我已有知识库的根目录作为--protect。我授权仅在第一套保存虚构样本，验证新增、读取、修改、归档恢复；第二套保持空白并核对文件未变。不要改全局规则、读取受保护库正文或注册真实定时任务。最后给出两套完整ID、绝对目录、实际验收结果和接续方式。

再次说“新建”会生成另一套；继续使用旧库时提供其root和完整ID，明确“接续，不新建”。

## 实测范围

现有程序在macOS、Python3.9.6下通过36项回归与35项集成检查。无原对话上下文的独立Agent成功建立两套同名库并完成读写验收；压缩包移到其他目录后也能独立创建空库。

未逐一验收所有第三方Agent、Windows或Linux。Obsidian界面接入与真实调度依赖宿主能力；没有工具时必须说明未接入。文件层完成不代表手机、云同步或通知送达已完成。
